# 探盘剪辑（实拍 Vlog 版）

目标：用户给一个文件夹（里面有边走边说的视频、空镜、照片，可能有楼盘资料、文案、参考脚本），交付一条**能直接发抖音**的竖版成片，再附发布文案和封面说明。

这个 skill 是在真实账号上把探盘片一条条磨出来后总结的。它给的是**做法、规矩和一套积木**，不是一个要复刻的成片。

## 最重要的一条：每条片子从它自己的文案和素材长出来

用户原话："不要写死，是根据文案和素材来的，不要每次都模仿我这个已经做好的。"

所以开工先做的是读和看，不是复制工程改字：

- 这条在讲什么？观点是什么、分几层、哪句最抓人——结构从这里来。有的片子是"两个盘对比"，有的是"一个盘从大门走到样板间"，有的是"三个避坑点"，有的就是一镜到底的带看。分不分章节、要不要对比、有没有清单、结尾引导什么，都看这条的内容，没有固定的段落模板。
- 手上有什么画面？每句话能配哪段实拍，决定了哪里露脸、哪里盖空镜、哪里干脆让实拍自己说话（留现场原声）。
- 包装为内容服务。`motion-template` 里的标签、分屏、章节号、大字、对照表只是积木：这条用得上就用，用不上就不用，需要新的就在 `Vlog.tsx` 里新写一个。连着两条片子的开头、章节形式、结尾卡长得一样，就是偷懒了。

## 探盘片要的感觉（和口播的区别）

用户否定过"人缩进圆环 + 米白讲解动画"那套做法："不还是跟口播一样吗"。探盘要的是**现场感和节奏**：

1. **实拍是主角。** 全程实拍画面，人物全屏出镜；不缩圆环、不铺米白 B-roll 背景、不做比喻动画。
2. **声音做主线，画面跟着话走。** 说到哪就切到哪段实拍盖上（声音不断、画面换）。人只在观点句和情绪句上露脸；连续只有人脸超过 10 秒就闷了，找实拍盖一下。
3. **只用这条的素材。** 不借别的视频的画面；口播提到但没拍到的东西，用现有的沙盘照/空镜做推拉和局部放大，别凭空画。缺得厉害就告诉用户"这里缺 XX 的实拍"。
4. **画面保持原色。** 不加滤镜、暗角、颗粒；广角畸变不矫正；Remotion 渲染都带 `--color-space=bt709`。
5. **包装轻。** 字幕、地点/楼盘小标签、关键数字、指实物的箭头——贴在实拍上，放在脸的旁边，不挡脸。大字冲击全片 ≤3 处。不加动画小人、卡通图标这类"AI 感"的东西。
6. **转场用拍摄里现成的动作**（走出大门、推门、甩镜、手挡镜头、前后动作接上），或者直接硬切；不用卡片转场。换场景时可以给一行小字交代（比如从小区切到车里）。
7. **开头前 3 秒要抓人。** 把全片最有冲击力的一句提到最前面当钩子（原位置删掉，别重复），或者用几个最好看的镜头快切；第 0 帧就有标题。具体用哪种看这条的素材。

## 硬规矩（用户明确提过，每条都要守）

- **不留结巴和重说。** 两句开头相同的重说留后一遍；句中卡住半秒以上的空白剪掉；口头禅式的拖尾（"……的一个位置"）可以剪。剪完必须把拼好的人声单独转写一遍复查（`verbatim_check.py`），因为整段转写会把重说合并掉、看不出来。正常的语气拉长不算结巴，别剪得不自然。
- **音效用真实录制的，不要程序合成。** 用户嫌合成音效"太 AI、太机械"。用 `public/sfx_real/` 里的 Mixkit 音效（免费可商用），不够就去 mixkit.co 再挑，**下载前把清单（名字、来源、大小）发给用户确认**。密度：任意 10 秒 ≤7 下、同一个声音全片 ≤3 次、连续同类动作只响首尾；比人声低 5–12 dB。探盘比口播用得少，一条 3 分钟的片子 30–40 处就够。
- **默认不加背景音乐。** 用户试过几版配乐都不满意，最后决定自己在剪映里加。所以默认交"无配乐版"（人声 + 现场声 + 音效）并附分轨，同时告诉用户哪几段没人说话、需要把配乐抬起来。用户主动要配乐时再看 `references/配乐（用户要求时）.md`。
- **先出 1080 给用户看，确认了再出 4K。** 4K 渲染要一个小时左右，用户通常还要改。用户会指定帧率（上次要的是 4K 60 帧）。
- **数字和事实以用户和资料为准，拿不准就问。** 楼盘名、面积、户型、口令（"评论区打 222"）听不清或资料对不上时，给选项让用户选，不要猜。画面上的数字跟口播说的保持一致。
- **资料里标了不能外传的（价格、房号、内部优惠）不上画面、不进文案。** 样板间画面常驻一行"样板间为装修效果 · 实际交付毛坯"（如果确实是毛坯交付）。提到学区写"以教育局当年划片为准"。不用"最""第一""必涨"这类绝对化的词。
- **抖音安全区**（1080×1920 设计坐标）：主信息放 x 33–975、y 112–1600；右侧按钮（x≈1010，y 875–1720）、底部文案区（y≥1607）、顶栏（y<112）别压东西。字幕一行 ≤11 个字，放在胸口位置不贴下巴。参考图 `references/抖音安全区参考.png`。
- **修改建议一次列全。** 用户问"还有什么可以优化"时，把看到的问题编号列成一张清单并标出推荐项，用户回编号后一次改完、只渲染一次。列之前先逐帧核对，别把不存在的问题列进去。
- 回复用户说人话（用户多半不是程序员）；长时间干活时隔一会儿说一句在做什么。

## 流程

`$S` = 本 skill 的 `scripts/`；`$M` = 这条的动效工程 `<工作目录>/.code/<项目名>/motion`；`$R` = 用户的素材目录；成果放 `$R/剪辑成果/`。Python 都带 `PYTHONIOENCODING=utf-8`。

### 1. 盘素材
- 列出所有文件；读文案、楼盘资料、参考脚本（docx 用 zipfile 解 `word/document.xml`，记得 UTF-8）。
- 每段视频 `ffprobe` 看分辨率/帧率/时长/有没有声音；`python $S/contact.py <视频> <目录> --step 2` 抽帧拼图，逐张看拍了什么、人在哪、手有没有入镜。照片直接看。
- 有人声的都转写：`ffmpeg -i x.mov -ac 1 -ar 16000 x.wav` → `python $S/transcribe.py x.wav x.json --terms "楼盘名 地名…"`。没人声的素材 whisper 会幻觉出一堆字，看平均音量（< -45 dB 基本是没声音）别当真。
- `python $S/speech_islands.py x.wav islands --thr -38` 拿到每句话的真实起止（whisper 的逐字时间常常偏早 0.3 秒，字幕和剪点以它为准）。
- 实测语速（字/秒）：目标 5.3 左右，倍率 = 5.4 ÷ 实测，范围 0.9–1.25；5.0–5.8 不调。

### 2. 出方案，先跟用户对齐
写 `$R/剪辑方案.md`：素材盘点表（每段是什么、打算怎么用）、成片结构（每段时间、声音、画面、包装）、风格卡（调性、配色、字体、节奏、音效密度——都按这条定，写明理由）、需要用户确认的问题（缺的素材、对不上的数字、要不要某段）。

风格拿不准时别闷头做：字体出样张让用户挑，结构有两种走法就问。然后**先剪开头 30–45 秒样片**给用户看感觉，对了再剪整条——这一步省过很多返工。

### 3. 剪点
- 逐句定保留段：删重说、删卡顿、收紧超过 0.6 秒的句间停顿。可疑的地方用 `python $S/energy.py <原片> 65.5:66.9` 看 20ms 能量表，把剪点放在静音谷里。b/p/d/t 这类爆破音开头前有一小段闭塞静音，别把它当成字间空隙切下去（会切掉半个字）。
- 钩子前置、挪句子顺序都可以，改动要在交付时告诉用户。
- 剪点处画面会跳：用实拍插入盖住，或用 `zoomcut`（跳切放大 8–12%）。

### 4. 搭工程
```bash
cp -r <skill>/motion-template $M
cd $M && npm ci        # 约 800 MB；做过一条之后，可以用目录联接复用同一份 node_modules，别每条都装
python $S/fetch_sfx.py $M/public/sfx_real   # 首次：按清单下载真实音效
python $S/make_proxies.py 清单.json $M/public            # 1080 代理，名字用英文，整段原速
```
- 在 `$M/scripts/build_main.py` 里照分镜写时间线（用 `tl_lib.py`：`play` 接主线、`at` 把原片秒数换成成片秒数、`insert` 盖实拍、`overlay` 加包装、`cue` 打音效）。格式和现有积木见 `references/时间线格式.md`。
- 积木不够就改 `src/Vlog.tsx`。新组件里的动画一律用 `useFrame30()` 取当前帧、用 `f30()` 换算时间，这样 30 帧和 60 帧渲染出来的动画时长一样；只有 `<Sequence>` 的起止和视频裁剪起点用真实帧 `f()`。
- 字体、配色在时间线里设（`colors`、`fonts`），字体文件放 `public/fonts/`。默认用得意黑 + 思源黑：从 `口播剪辑/assets/fonts/` 把 `SmileySans-Oblique.ttf`、`NotoSansSC-Medium.otf` 拷进 `public/fonts/`；别的风格的字体也在那里。

### 5. 声音
```bash
python $M/scripts/audio_mix.py $R $R/剪辑成果/工作素材/声音 --name <片名>     # 人声+现场声+真实音效 → -16 LUFS；同时出分轨、字幕 srt、无人声时段清单、人声16k
python $S/verbatim_check.py $R/剪辑成果/工作素材/声音/<片名>_人声16k.wav --terms "…"   # 复查结巴重说
```
不同场景录的人声会自动对齐响度。脚本会打印每段素材的底噪：户外有风声车声、标了“偏吵”的，加 `--denoise` 重混一遍再听（只压稳态底噪，不会把现场感抠没）。`public/sfx_real/` 里没有 mp3 时先跑 `python $S/fetch_sfx.py $M/public/sfx_real`。讲到现场的东西（车流、鸟叫、样板间里销售的讲解）可以垫一点或直接留现场原声，比配音效更真。

### 6. 渲染、检查、交付
```bash
cd $M && python scripts/build_main.py && npx tsc --noEmit && npx remotion bundle --out-dir ../bundle
npx remotion still ../bundle Main ../stills/x.jpg --frame=N --scale=0.4 --gl=angle --color-space=bt709      # 每个新包装出现后 0.9 秒各抽一帧，拼图看
npx remotion render ../bundle Main ../muted.mp4 --gl=angle --muted --codec=h264 --crf=17 --color-space=bt709  # 1080，后台跑
ffmpeg -i ../muted.mp4 -i <混音.wav> -map 0:v -map 1:a -c:v copy -c:a aac -b:a 256k -shortest -movflags +faststart <成片_1080.mp4>
python $S/contact.py <成片> ../sheets --step 2 --cols 12 --rows 6        # 整条再过一遍
python $S/safearea_check.py <成片> ../safearea --step 2                  # 叠上抖音按钮和文案区的遮罩，看文字有没有被盖住
```
逐张看：有没有挡脸、文字出画或重叠、字幕超宽、标签跟画面对不对得上（楼盘名别贴反）、纯人脸段是否太长。把成片发给用户，说明：改了/删了什么、哪些文字是口播里没有而你加的、哪些字幕是听不清按上下文写的（请用户确认）、哪些检查过、哪些没法检查（声音好不好听要用户戴耳机听）。改版另存 `_第N版`，不覆盖旧的。

**出 4K（用户确认 1080 之后）：**
```bash
python $S/make_proxies.py 清单.json $M/public --4k [--fps 60]
VLOG_FPS=60 VLOG_CLIPDIR=clips4k python scripts/build_main.py            # 要 30 帧就不设 VLOG_FPS
npx remotion bundle --out-dir ../bundle4k
npx remotion still … --scale=2    # 先抽几帧跟 1080 版同一时间点对比，画面应该一模一样
npx remotion render ../bundle4k Main ../4k_muted.mp4 --scale=2 --gl=angle --muted --codec=h264 --crf=15 --color-space=bt709
```
渲染前想办法别让电脑休眠。中途停掉渲染后要清残留的 chrome-headless-shell / ffmpeg / node 进程。

**最后的交付物**（`$R/剪辑成果/`）：成片（无配乐）、人声/音效分轨 wav、字幕 srt、无人声时段清单（方便用户加配乐）——后几样 `audio_mix.py` 都会出。

**定稿后清理**：一条片子的中间文件有十几个 GB（各版无声渲染、试听、4K 代理）。用户说定稿了，跑 `python $S/clean_project.py <项目目录>` 列出能删的和大小，**给用户看过、同意后**再加 `--delete`。

**用户要发布时**再给：标题备选、作品描述 + 话题、封面说明和参考图，写法见 `references/发布文案与封面.md`。

## 做完之后
用户给了新的偏好或否定了某种做法，除了记进记忆，也回来改这个 skill（规矩写进上面，新积木留在模板里），让下一条少走弯路。
